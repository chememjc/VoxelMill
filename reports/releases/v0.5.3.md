# VoxelMill 0.5.3 alpha verification

Verification date: 2026-09-20. This record distinguishes the local acceptance
artifact from the tag workflow's published artifact.

## Implementation

Main support pillars remain. Branches descend at 45° from full-width shoulders,
using 15 mm vertical spacing and a 30 mm maximum diagonal length by default.
Neighbour reach and primary support spacing remain separate. Primary
part-to-part routing requires explicit enabling; brace networks always require
support-only grounding. Geometry tests cover shared junctions, unequal heights,
elbows, duplicate suppression, thickness clearance, multiple model parts,
complete feet, boundaries, tree supports, cancellation and work limits.

Prepared-mesh tests inspect exact reopened connectivity and decoded layers.
Grid bases receive a precision-bounded simplification before STL serialization
to prevent collapsed faces. Separate regressions retain honest drainage
rejection where low braces narrow an otherwise open channel.

## Release gates

Before committing, `VOXELMILL_SAMPLES=1 .venv/bin/python -m pytest -q -ra`
passed **1,173 tests**, with 8 skips, in 240.09 seconds. This includes the
available original-model tests and actual-render GUI tests. Skips: one missing
immutable reference GOO, five FreeCAD-dependent tests, and the unavailable
zsh/fish completion tests. Local AppImage acceptance also passed before commit.

The existing `release` workflow must next pass Linux, macOS ARM, macOS Intel
and Windows on the pushed commit before `v0.5.3` is tagged. Published-artifact
provenance and acceptance will be recorded here after the tag workflow completes.

The additional benchmark comparison used the existing historical baseline.
All six timings improved, but `slice_small` peak RSS was 220,348,416 bytes
versus 172,560,384 bytes (27.7% above baseline), exceeding its 15% memory
threshold. This is recorded separately from the passing functional suite and
AppImage acceptance; the baseline was not rewritten to conceal the result.

## Coverage limits

Linux acceptance uses Xvfb and actual VTK rendering. macOS and Windows runtime
acceptance and physical printer trials are outside this Linux verification;
their portable builds and CLI smoke checks are required in GitHub Actions.
