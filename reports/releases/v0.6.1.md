# VoxelMill 0.6.1 beta verification

Release candidate artifacts for macOS and Windows come from release workflow run
<https://github.com/chememjc/VoxelMill/actions/runs/36512665235>
(`platforms=mac+windows`), built from commit `825726a`. The Linux AppImage was
built locally from the same commit. The commits after `825726a` change only
this record.

Testing the first candidate (`69b632d`) found three problems, which were fixed
before this candidate was built:

- `b87e69a`: on the Intel iMac an idle editor still re-rendered at about 25 Hz,
  because each Cocoa render raises its own paint.
- `77b19f6`: no `.voxmil` could be opened on any Mac, because the temporary
  directory lies under the root-owned `/var` symlink. This bug predates 0.6.1.
- `825726a`: `voxelmill gui part.voxmil` read the project archive as an STL.

## Changes

See `packaging/release-notes.md` for the user-facing list. In short:

- Import STEP adds to the plate instead of replacing it, and Open STL, Import
  STEP and Add model take several files.
- The rotation gizmo composes rotations from the current pose, so a second ring
  no longer snaps back to the import pose.
- The macOS 3D view no longer repaints in a loop, which fixes slow pane
  resizing.
- Knife-edge islands get model stubs, and routed tips are reserved.
- Support failures say why they happened and which settings to change, in the
  report and in the editor.
- Tree trunks have their own diameter, 1.2 mm by default.
- Reports split resin use into model, supports and total, in mL and g.

## Local test suite (Linux)

- `pytest -m "not samples"`: **1,533 passed, 7 skipped**.
- Golden reports were re-recorded after review. Every change was an added key,
  except on the sphere and torus: once tips are reserved, braces that would
  cross a tip are rejected, so different braces are chosen. No check verdict
  changed.
- ruff and mypy are clean.

The user project that motivated the support work is a STEP-derived part at
(0, 15, −35). In 0.6.0 it withheld export with three unroutable 1-pixel
islands. It now prepares with 79/79 contacts, zero islands and
`support_collisions` passing, with the saved settings, with `--tree-supports`
and with `--no-tree-supports`. On the float valve cover the seven
tip-to-anchor overlaps of VM-097 are gone.

## Known issues

- VM-096: exact-union exports of the torus and bracket can hold zero-volume
  folds that the strict importer refuses. Slicing is unaffected.
- The editor's island badge counts islands of the model as loaded, before
  supports are routed. A project or part opened without computing attachments
  shows a red count, for example 9 for the user project and 1 for the cube,
  even though `prepare` passes. Compute attachments updates it.

## Coverage limits

- Linux acceptance uses Xvfb and actual VTK rendering.
- Windows runs in a VirtualBox guest on software OpenGL, not real hardware.
- The Apple Silicon DMG (SHA-256
  `c218012dc80989f57201b96d2a10a3560f96d8fdf7861b03072156df40840329`) was
  built but not run: no Apple Silicon host.
- Physical printer trials are outside this verification. Nothing here certifies
  print strength, drainage or printability.
