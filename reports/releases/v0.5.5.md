# VoxelMill 0.5.5 alpha verification

Release candidate artifacts come from release workflow run
<https://github.com/chememjc/VoxelMill/actions/runs/35956887547>, built from
commit `8132060`. The application code at the release tag is identical: the
commits between that run and the tag change tests, CI, documentation and the
AppImage builder's Python-version guard only.

## Changes

See `packaging/release-notes.md` for the user-facing list. In short: the
editor's outlines render under generic OpenGL (VirtualBox guests); hex infill,
the wall-thickness memory budget, the editor job pool and scratch cleanup,
Windows core detection and the editor's settings controls are fixed; slicing
works from the part's footprint rather than the whole panel (small part at 9K
24.6 s → 1.3 s, 4-level antialiasing 151 s → 13 s, identical layer bytes);
large 16K parts prepare and slice several times faster; `info` replaces
`goo-info`/`ctb-info` (kept as aliases); usage errors exit 64.

Support routing no longer depends on the NumPy build. Downward-face samples
were computed with `mean()` and matrix products whose rounding differs between
NumPy/BLAS builds and CPUs; thinning rounds samples to spacing cells, so a
one-ulp difference moved contacts. Samples now use explicit elementwise sums
and tie-sensitive sorts are stable. Reports match 18/18 between NumPy 1.26 /
SciPy 1.12 and NumPy 2.2 / SciPy 1.15.

## Local test suite (Linux)

`pytest -m "not samples"`: **1,309 passed, 7 skipped** (unavailable reference
GOO, FreeCAD not installed, zsh/fish absent). Golden reports 18/18. ruff and
mypy clean.

## Continuous integration

The new `ci` workflow ran on GitHub for the first time with this release. Lint
and types and the Python 3.10 test leg pass. The Python 3.12 leg failed only on
an AppImage-builder test that assumed the builder's CPython 3.10 guard ran after
staging; the guard now sits in the staging function itself. The golden-report job is advisory:
after the sampling fix the runner matches 16 of 18 scenarios, the remainder
being last-bit differences from transcendental math on a different CPU path.

## Coverage limits

Linux acceptance uses Xvfb and actual VTK rendering. Windows runs in a
VirtualBox guest on software OpenGL, not real hardware. macOS was tested from
the command line on an Intel iMac; the Apple Silicon build is produced by the
workflow but no Apple Silicon host was available. Physical printer trials are
outside this verification, and nothing here certifies print strength,
drainage or printability.
