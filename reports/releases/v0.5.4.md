# VoxelMill 0.5.4 alpha verification

Verification date: 2026-09-22. This record distinguishes the local acceptance
artifact from the tag workflow's published artifact.

## Implementation

Support routing gains configurable brace destinations, density, angles, and
single/alternating/X patterns, visible brace distance controls, and continuous
angled/tree tip joints. A `showcase` example layout puts every route kind in
one picture: a plate route, a branch around a blocker, a model anchor, a thin
model pillar, a supported raster island, and the brace network. It forces the
six settings those routes need, copying the caller's settings rather than
editing them, and reports which values actually differed. It analyses at the
production column pitch, because the surface a model anchor lands on is read
from that raster and a demo of anchor placement should not be the one place
that is approximated more coarsely than a real job.

The editor's navigation cube now classifies all 26 facets it draws: six faces,
eight corners, and the twelve 45 degree bevels that previously fell through to
no result. Facet outlines are precomputed perimeter loops rather than a mesh
edge flag, so no face carries its own triangulation diagonal, and no filter
runs inside a paint. Orbit arrows step 45 degrees instead of 90, matching those
bevels, and two roll buttons turn the view in its own plane. Arrow hit testing
now follows each glyph's own triangle rather than claiming an outer band, which
is what allowed the glyphs to move close to the cube without shadowing the
cube's own picks.

Field documentation is one shared table read by both the generated Setup rows
and the dedicated editors; every one of the 148 generated rows carries an
explanation, where previously the part-to-part and thin-pillar keys carried
none in either surface. Anchor and thin-pillar settings are separate editor
tabs, since thin pillars in middle mode apply to every pillar. The hover delay
is an editor preference applied through a proxy style, since Qt reads that
delay from the style and not from the widget. The Report tab lists report
fields as parameter rows while still returning the identical JSON on request.

A leftover autosave previously stopped every non-interactive launch on a
recovery prompt with nobody to answer it; that prompt now skips on the same
gates as the first-run wizard and leaves the autosave for the next interactive
start. `gui --screenshot` captures the window, 3D view composited in, with no
screen-recording permission, which is what makes unattended visual evidence
possible over SSH.

Two defects were found by review after the first commit and fixed in the
second. The showcase layout's branch station stopped branching at wide spacing
over a short bar, because the branch's sideways detour grows with the block's
width while the drop to the plate does not; the block's width is now capped
against the bar height, and the layout is checked across 80 combinations
spanning the accepted spacing and height ranges. Below 8 mm of height the
structure is shorter than the fixed 2 mm tip and 2 mm bottom connector standing
in it and the branch case cannot be produced at all, so the showcase now
refuses that outright rather than quietly returning four kinds out of six; the
other two layouts keep the full 3 to 160 mm range. Separately, the report
parameter view's `toPlainText` raised on a payload with unserializable keys,
which would have broken the Copy action rather than showing a value; it now
always returns a string.

## Local test suite

`VOXELMILL_SAMPLES=1 pytest -q -ra`: **1,271 passed, 8 skipped** on Linux. The
skips are environmental: an unavailable immutable reference GOO, five FreeCAD
tests with no FreeCAD present, and zsh/fish completion tests with neither shell
installed.

Support struts are checked for reaching what they were routed to by unioning
the router's own solids and requiring a single connected component. Sampling
the column under a contact cannot answer this, because a branched or slanted
strut legitimately leaves that column. All three example layouts pass.

Benchmark comparison against the existing historical baseline: every row with a
baseline improved (`prepare_small` 11.65 s to 1.27 s, `validate_small` 11.43 s
to 1.01 s, `slice_small` 32.69 s to 22.31 s, `verify_small` 15.91 s to 5.74 s,
`prepare_bracket` 60.44 s to 3.56 s); `inspect_small` measured 0.20 s against
0.18 s, within tolerance. Exit codes matched the baseline exactly. The sample
rows were not compared because the baseline records `samples_included: false`.

## Coverage limits

Linux acceptance uses Xvfb and actual VTK rendering. macOS runtime acceptance
is limited to an Intel iMac; **no Apple Silicon host and no Windows host were
available**, so those two platforms are covered only by their GitHub Actions
builds and this source audit, not by runtime testing. Physical printer trials
are outside this verification.
