# VoxelMill 0.6.0 beta verification

Release candidate artifacts for macOS and Windows come from release workflow run
<https://github.com/chememjc/VoxelMill/actions/runs/36064258383>
(`platforms=mac+windows`), built from commit `7d81759`. The Linux AppImage was
built locally from the same commit. The commits after `7d81759` change only
this record.

## Changes

See `packaging/release-notes.md` for the user-facing list. In short: default
supports pass validation on every valid test shape and look like CHITUBOX
Light; braces can join pillars that stand on the model (off by default); a
rescue pass braces pillars starved in dense rows; every `prepare` audits
support collisions; `slice`, `verify` and `validate` warn instead of failing
on support crevices they cannot attribute; the editor gains a ranked settings
search, typed pages for every section, a shortcut editor, a layer pixel
readout and profile-library prompts; islands are re-checked after support
generation rather than after every edit.

## Local test suite (Linux)

`pytest -m "not samples"`: **1,449 passed, 7 skipped** (unavailable reference
GOO, FreeCAD not installed, zsh/fish absent). Golden reports 18/18 against the
re-recorded set. ruff and mypy clean.

Default fixtures, plate pillars: every one keeps its longest unbraced run at or
under a slenderness of 15 (worst: the bracket, 10.0 mm, 11.1). With
`--brace-model-pillars` the bracket braces 16 of its 17 model-standing pillars
and their worst run drops from 22.6 mm to 9.9 mm.

The two float valve parts from `docs/examples.md` now go through `prepare`,
`slice` and `verify` with exit 0 each; in 0.5.5 `slice` withheld both.

## Known issues

- VM-097: on the float valve cover, seven tips touch a neighbouring model
  anchor's foot; `prepare` reports it as a `support_collisions` warning.
- VM-096: exact-union exports of the torus and bracket can hold zero-volume
  folds that the strict importer refuses; slicing is unaffected.

## Coverage limits

Linux acceptance uses Xvfb and actual VTK rendering. Windows runs in a
VirtualBox guest on software OpenGL, not real hardware. The Apple Silicon DMG
was built by the workflow but not run here: no Apple Silicon host was
available. Physical printer trials are outside this verification, and nothing
here certifies print strength, drainage or printability.
